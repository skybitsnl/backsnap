# CLAUDE.md

Kubebuilder operator (Go, controller-runtime). For what Backsnap does and how
to run/test/build it, read [README.md](README.md) ("How does it work?" and
everything from "Contributing" down).

## Way of working

- Do not commit yourself. Stop and ask the user to commit. Suggest a commit
  message.
- For new developments, begin with a design, and check it with the user before
  writing code, unless the change is small and the user does not ask for a
  design first.
- When the user asks you to write new code, do not broaden the scope without
  checking with the user. Remember that commits and PRs are reviewed by a human,
  so keep them small and to-the-point. Split up commits or PRs if necessary. Keep
  refactorings in their own commits or PRs unless they are very small.

## Layout

- `api/v1alpha1/` – `PVCBackup` and `PVCRestore` CRD types (group `backsnap.skyb.it`).
- `internal/controller/automatic.go` – watches PVCs/namespaces and creates
  `PVCBackup`s on a cron schedule (`backsnap.skyb.it/schedule` annotation).
- `internal/controller/pvcbackup_controller.go` – per `PVCBackup`: VolumeSnapshot
  → temporary PVC from it → Job running the restic image → cleanup after TTL.
  The snapshot, PVC and Job all share the `PVCBackup`'s name/namespace and are
  owned by it. Concurrency (`-max-running-backups`) is tracked in memory.
- `internal/controller/pvcrestore_controller.go` – creates a PVC and a Job that
  runs `restic restore` into it.
- `restic.sh` + `Dockerfile.restic` – the backup Job's image
  (`sjorsgielen/backsnap-restic`). Restic repo per PVC is
  `s3:<host>/<bucket>/<namespace>/<pvc>`.

## Gotchas

- After changing API types or `+kubebuilder:rbac` markers, run `make` to
  regenerate `zz_generated.deepcopy.go`, `config/crd/bases` and
  `config/rbac/role.yaml`. CI fails if `make` leaves a diff.
- `chart/templates/{crd,rbac}`, `chart/templates/service_account.yaml`,
  `chart/README.md` and `chart/Chart.yaml` are generated by `chart/bump.sh`
  (needs `gsed`); don't edit them by hand. `chart/release.sh` packages the chart
  into `docs/`, which is the Helm repo served via GitHub Pages.
- `make test` runs Ginkgo e2e tests against a real cluster and refuses any
  kubectl context other than `minikube`. It deploys RustFS (as S3 backend) and runs real Jobs,
  so it is slow. Never point it at another cluster.
- The tests pull a *published* restic image (see `Image:` in
  `pvcbackup_controller_test.go`), so local changes to `restic.sh` are not
  exercised until that image is rebuilt and pushed.
- Logging uses `log/slog`.
- Releases: pushing a git tag triggers e2e + goreleaser (binaries and
  multi-arch images for both the operator and restic image).
